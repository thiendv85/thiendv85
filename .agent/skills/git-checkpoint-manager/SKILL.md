# Goal
Tạo "chốt chặn an toàn" bằng Git trước khi người dùng điều chỉnh code, tự động đẩy lên GitHub/Vercel, và duy trì một file danh sách lịch sử trực quan (đọc bằng tiếng Việt) để khôi phục nhanh chóng mà không cần nhớ dòng lệnh rườm rà.

# Instructions
1. **Khi người dùng gọi "backup git":**
   a. Nếu user chưa cung cấp tóm tắt thay đổi, hãy hỏi: *"Anh ghi chú gì cho bản backup này để sau này dễ xem lại ạ?"*
   b. Nếu user đã đưa tóm tắt, đọc file `backup_history.md` ở thư mục gốc (nếu chưa có thì tự động tạo mới file này với format bảng).
   c. Thêm 1 dòng cập nhật vào bảng trong file đó: `| YYYY-MM-DD HH:mm | [Tóm tắt công việc của user] |`.
   d. Chạy tuần tự các lệnh Git qua terminal: 
      - `git add .`
      - `git commit -m "Backup: [Tóm tắt công việc]"`
      - `git push`
   e. Báo cáo bằng thái độ hào hứng: *"Backup an toàn lên GitHub & Vercel rồi anh nhé! Code thoải mái đi anh!"*

2. **Khi người dùng gọi "xem git" (hoặc muốn khôi phục lịch sử):**
   a. Dùng lệnh đọc nội dung file `backup_history.md` tại thư mục gốc đưa cho user xem.
   b. In ra màn hình file đó dưới dạng text dễ nhìn nhất.
   c. Chạy ngầm thêm lệnh `git log -n 10 --oneline` để lấy mã hash (nếu user yêu cầu khôi phục).
   d. Hỏi user: *"Anh có muốn khôi phục về bản nào không? Cứ đọc ngày hoặc nội dung, em sẽ lo câu lệnh Git giúp anh."*

3. **Khi người dùng yêu cầu Khôi phục (Restore về bản cũ):**
   a. Phân tích yêu cầu để lấy đúng mã hash của commit cũ.
   b. BẮT BUỘC kiểm tra `git status` trước. Nếu có code đang làm dở (Uncommitted changes), CẢNH BÁO user và yêu cầu `git stash` hoặc commit/backup trước khi khôi phục.
   c. Để an toàn, luôn đề xuất 2 cách:
      - `git checkout <hash>`: Phù hợp để "quay về quá khứ" chạy thử code cũ xem lỗi do đâu, không ảnh hưởng code hiện tại.
      - `git revert <hash>`: Tạo 1 mũi tên đảo ngược thay đổi, rất an toàn mà không làm mất lịch sử.
   d. Thực thi lệnh theo ý user và báo cáo kết quả.

# Examples
## Ví dụ 1: Tạo backup mới nhanh gọn
**User:** "backup git, chuẩn bị thay đổi cấu trúc DB nhé em"
**AI (Action):**
- Thêm vào file `backup_history.md`: `| 2026-03-20 08:30 | Chuẩn bị thay đổi cấu trúc DB |`
- Lệnh Terminal: `git add . && git commit -m "Backup: Chuẩn bị thay đổi cấu trúc DB" && git push`
**AI (Response):** "Đã lưu bản checkpoint vào `backup_history.md` và push lên GitHub an toàn! Vercel cũng đang Deploy bản chạy nền rồi. Phá code thoải mái đi anh! 🚀"

## Ví dụ 2: Lấy danh sách backup

**AI (Action):** Đọc file `backup_history.md` và hiển thị ra cho user.
**AI (Response):** 
```markdown

| 2026-03-20 08:30 | Chuẩn bị thay đổi cấu trúc DB |

```
"Đấy anh, lịch sử ghi lại rõ ràng. Anh muốn xem hoặc khôi phục về bản nào không?"

# Constraints
- LUÔN LUÔN ghi chép vào `backup_history.md` TRƯỚC KHI `git commit`. Điều này đảm bảo lịch sử thay đổi luôn được track lại dạng text để con người dễ đọc, và file này cũng được backup.
- Bắt buộc kiểm tra `git status` trước khi khôi phục code (restore) để tuyệt đối KHÔNG vô tình xóa mất code đang viết dở của user.
- KHÔNG BAO GIỜ tự ý dùng lệnh `git reset --hard` trừ khi đã giải thích rõ hậu quả (xóa vĩnh viễn code dở dang) và user CỰC KỲ quả quyết gõ lệnh xác nhận. Luôn ưu tiên `checkout` hoặc `revert`.
